## Обзор проекта

Основная цель — преобразовать сырые, разнородные данные о пациентах в чистый, структурированный набор данных, готовый для построения прогностических моделей машинного обучения. В ходе анализа решаются следующие задачи:

*   Объединение данных из различных источников (справочники, измерения, события).
*   Очистка данных от выбросов и невалидных значений.
*   Анализ пропусков и их заполнение (импутация).
*   Создание новых признаков (например, `ИМТ`, `пульсовое_давление`).
*   Анализ распределений и корреляций.
*   Агрегация измерений на уровне пациентов для ML.
*   Формирование целевых переменных (бинарная, мультиклассовая, регрессионная) на основе количества клинически значимых событий.
*   Подготовка данных для анализа временных рядов.
*   Кластеризация пациентов с использованием алгоритма GDTW.

## Данные

Анализ использует несколько CSV-файлов, которые должны находиться в папке `Downloads/`:

*   **`Идентификаторы Субъектов 10.04.2025.csv`**: Справочник субъектов РФ (`id субъекта`, `название субъекта`).
*   **`Идентификаторы МО 15.04.2025.csv`**: Справочник медицинских организаций (МО).
*   **`МО и Пациенты 10.04.2025.csv`**: Связка "пациент-программа", содержащая информацию о том, к какой группе наблюдения относится пациент (`группа наблюдения`: опыт, контроль, реальная практика).
*   **`Первичные данные от 10.04.2025.csv`**: Основной файл с измерениями (САД, ДАД, ЧП, рост, вес, дата/время измерения и т.д.). Это самый объемный файл.
*   **`Медикаментозная терапия от 10.04.2025.csv`**: Данные о назначенной терапии (МНН — международное непатентованное наименование).
*   **`Клинически значимые события от 15.04.2025.csv`**: Данные о произошедших КЗС у пациентов.

## EDA

### Загрузка данных
Загрузка всех необходимых файлов с использованием `pandas`. Для большого файла `Первичные данные...` используется чтение по частям (chunks), чтобы избежать нехватки памяти.

### Проверка целостности
Проверка связей между таблицами и наличия дубликатов. На этом этапе происходит объединение таблицы `patient_program` со справочником субъектов для получения `id субъекта`. Также проверяется, все ли `id МО` из таблицы пациентов есть в справочнике МО.

### Очистка данных
Преобразование колонок с датами и временем в формат `datetime`. Преобразование числовых полей (САД, ДАД, ЧП, рост, масса) в числовой формат с обработкой ошибок. Расчет возраста пациента на момент измерения.

### Outlier Analysis
Выявление и анализ аномальных значений:
*   Физиологические границы для САД, ДАД, ЧП и возраста.
*   Проверка на будущие даты.
*   Анализ слишком частых измерений для одного пациента в день.

### Анализ по группам
Добавление информации о группе наблюдения к первичным данным. Анализ распределения пациентов по группам и базовой статистики измерений внутри каждой группы.

### Визуализация
Построение первичных графиков для понимания распределений основных показателей (САД, ДАД), их соотношения и активности измерений по часам.

### Анализ КЗС и терапии
Анализ таблицы с клинически значимыми событиями: топ-10 событий, статистика их количества на одного пациента. Анализ терапии: топ-10 назначаемых МНН.

### Сохранение и статистика
Удаление выбросов, выявленных на Этапе 4. Сохранение первых версий очищенных данных (`primary_clean.csv`, `patient_program.csv`, `kzs.csv`, `therapy.csv`) и вывод итоговой статистики по датасету.

### Детальная EDA и анализ по группам
Более глубокая визуализация и анализ, включая:
*   Детальные графики распределений с указанием средних и медиан.
*   Корреляционный анализ.
*   Сравнение поведения разных групп наблюдения (боксплоты, гистограммы, статистика).

### Анализ качества данных
Оценка качества собранных данных:
*   Процент пропусков в критических полях по группам.
*   Регулярность измерений (сколько месяцев пациент участвует в исследовании).
*   Анализ задержки передачи данных на сервер.

### Очистка дубликатов и анализ ночных измерений
*   **Удаление дубликатов:** Поиск и удаление записей с одинаковым `id пациента` и `время измерения`.
*   **Анализ ночных измерений:** Исследование доли измерений, приходящихся на ночное время (22:00 - 6:00). Анализ по часовым поясам и попытка коррекции времени, если данные хранятся в UTC.

### Импутация пропусков
Заполнение пропущенных значений:
*   Рост и вес заполняются медианными значениями для группы пациентов того же пола, возрастной группы и группы наблюдения.
*   Категориальные поля заболеваний заполняются значениями-заглушками ("Не указано", "Нет данных").
*   На основе заполненных данных создаются новые признаки: **ИМТ (индекс массы тела)** и **пульсовое давление**.
*   Проводится анализ и коррекция аномальных значений ИМТ.

### Финальные исправления и целевая переменная
Финальная подготовка данных для машинного обучения:
*   Исключение пациентов с аномальными значениями ИМТ (>50) или малым количеством измерений (<5).
*   Агрегация всех измерений по каждому пациенту в набор статистических признаков (среднее, медиана, стандартное отклонение, мин, макс, межквартильный размах) для САД, ДАД, ЧП и пульсового давления.
*   Добавление числа КЗС для каждого пациента.
*   **Создание целевых переменных:**
    *   `target_high_risk`: Бинарная переменная (1 - если число КЗС выше медианы).
    *   `target_risk_category`: Мультиклассовая переменная (Низкий, Средний, Высокий, Очень высокий риск).
    *   Регрессионная задача — предсказание абсолютного числа КЗС.

## Подготовка данных для временных рядов

На этом этапе данные были подготовлены для анализа временных рядов с использованием GDTW.

### Отбор пациентов
- **Критерий для кластеризации:** ≥30 дней наблюдения (отобрано 7 500 пациентов).

### Создание дневных агрегатов
Для каждого пациента были рассчитаны средние дневные значения по четырем показателям: САД, ДАД, ЧП и пульсовое давление.

### Нормализация
Все временные ряды были нормализованы методом Z-score (центрирование относительно среднего и масштабирование на стандартное отклонение). Это позволило сравнивать не абсолютные значения давления, а динамику изменений относительно индивидуального уровня каждого пациента.

## Кластеризация пациентов на основе GDTW

### Реализация алгоритма GDTW
Был реализован модифицированный алгоритм DTW с учетом временного фактора. В отличие от классического DTW, который сравнивает только форму рядов, GDTW добавляет штраф за временной сдвиг:

**Стоимость сопоставления = (Разница значений)² + γ × (Временной сдвиг / Окно)²**

**Параметры:**
- Временное окно: **14 дней** (максимально допустимый сдвиг).
- Гамма (γ): **1.0** (вес временного штрафа).
- Основной показатель: **САД** (наиболее клинически значимый).

### Вычислительная оптимизация
Для масштабирования на **7389 пациентов** потребовалось вычислить **~27.3 миллиона пар**:
- Использована JIT-компиляция (Numba) для ускорения вычислений.
- Применена векторизация расчетов временных разниц.
- Среднее время на одну пару: **менее 0.4 миллисекунды**.

### Матрица расстояний
- Размерность: **7389 × 7389**.
- Диапазон расстояний: **2.48 - 244.24**.
- Среднее расстояние: **72.15**.
- Медиана расстояния: **72.93**.
- Плотность матрицы: **~100%** (алгоритм нашел пути сопоставления для подавляющего большинства пар).

**Визуальный анализ матрицы выявил:**
- Неоднородную структуру с блочными областями, что говорит о естественной группировке пациентов.
- Положительную корреляцию между GDTW расстоянием и разницей в количестве КЗС (коэффициент 0.161) — пациенты с разной частотой кризов имеют более различные временные ряды.

### Определение оптимального числа кластеров
Были протестированы два подхода:
- **Silhouette Score:** максимум при k=2 (0.330), при k=3 показатель снижается до 0.220.
- **Метод локтя:** перегиб при k=3.

**Итоговый выбор: k = 3** (компромисс между математической оптимальностью и клинической интерпретируемостью).

### Характеристики полученных кластеров

| Кластер | Размер | Среднее КЗС | Характеристика |
|:---|:---:|:---:|:---|
| **Кластер 1** | 815 | **242.9** | Нестабильные пациенты с частыми кризами, высокая волатильность |
| **Кластер 2** | 4200 | **109.3** | Стабильные пациенты, минимальное число кризов |
| **Кластер 3** | 901 | **171.1** | Промежуточная группа, умеренный риск |

**Ключевое наблюдение:** Чем выше волатильность временного ряда, тем чаще случаются кризы. GDTW успешно разделил пациентов по степени стабильности их гемодинамики.

## ClusterBP v2: прогноз клинически значимых событий

Вторая версия пайплайна ClusterBP: GDTW-фенотипы + гибрид GRU и XGBoost + слияние их прогнозов. По сравнению с первой версией:

*   **Два типа событий** вместо одной смешанной цели: **A** — острый подъём АД (коды 33012, 33901, 33902) и **B** — превышение целевого АД, признак неэффективной терапии (33601, 33801, 33802, 33810, 33911). Старая цель сохранена как **OLD** для сравнения.
*   **Причинная постановка:** окна и события на одной шкале времени (время сохранения на сервере); между окном истории и горизонтом прогноза зазор 1 день для A и 7 дней для B, чтобы цель не вычислялась по входным измерениям.
*   **Расширенный набор признаков** XGBoost-модуля (XGB_full): пики и вариабельность АД (ARV), наклоны, доли измерений выше 140/160/180, ДАД, ЧП, режим измерений, история событий до момента прогноза.
*   **Строгая оценка:** 5-fold CV с разбиением по пациентам; ранняя остановка, пороги и веса смеси подбираются на внутренней валидации; фенотипы строятся только по обучающим пациентам и по прошлому окна; метрики при реальной доле событий; 95% ДИ бутстрепом по пациентам; сравнение с клиническими правилами.
*   **Временная валидация:** обучение до 01.10.2024, тест на октябре 2024 – январе 2025, отдельно на новых пациентах.
*   **Сравнение с mixture of experts** (обучаемый гейт по фенотипам, MoE-гейт по признакам пациента, остаточные эксперты).
*   **Интерпретация несколькими методами** (SHAP, permutation importance, Integrated Gradients, окклюзия по времени) с проверкой согласия и адекватности.

### Ноутбуки и порядок запуска

| Ноутбук | Что делает | Время на CPU |
|:---|:---|:---|
| `clusterbp_v2.ipynb` | Очистка выгрузки, окна и признаки, фенотипы, 5-fold CV всех моделей, бутстреп | ~35 мин + ~1 ч бутстреп (первый запуск) |
| `clusterbp_v2_temporal.ipynb` | Временная валидация | ~10 мин |
| `clusterbp_v2_moe.ipynb` | Сравнение со схемами mixture of experts | ~25 мин |
| `clusterbp_v2_interpret.ipynb` | Интерпретация: группы признаков, каналы, окклюзия, проверка адекватности, физиология, разборы окон | ~6 мин |

`clusterbp_v2.ipynb` запускается первым: остальные используют его окна, модели фолдов и предсказания. Общий код — в `clusterbp_lib.py`, зависимости — в `requirements.txt`.

Исходная выгрузка оператора кладётся в папку `2025_04_15/` в корне репозитория. Она, как и промежуточные данные (`cache_v2/`), в git не хранится. Быстрый прогон на 1 500 пациентах: `CLUSTERBP_DEBUG=1` (результаты пишутся в `cache_v2_debug/` и `results_v2_debug/`).
